'''

== Goal

1. Every block in a feature method (except `where:` and `filter:`) gets `SpockRuntime.callBlockEntered(this, blockIndex)` prepended and `SpockRuntime.callBlockExited(this, blockIndex)` appended to its statements.
2. Every feature method ends with `this.getSpecificationContext().getMockController().leaveScope()`.

'''

== Context and Motivation

=== Spock's Behaviour

From Spock's `SpecRewriter.addBlockListeners()` and the AST snapshot `all_observable_blocks_with_labels_and_blocks.groovy`:

[source,groovy]
----
@FeatureMetadata(blocks = [
  @BlockMetadata(kind = SETUP, texts = []),
  @BlockMetadata(kind = EXPECT, texts = [])
], ...)
public void $spock_feature_0_0() {
  org.spockframework.runtime.SpockRuntime.callBlockEntered(this, 0)
  // setup block statements
  org.spockframework.runtime.SpockRuntime.callBlockExited(this, 0)
  org.spockframework.runtime.SpockRuntime.callBlockEntered(this, 1)
  // expect block statements
  org.spockframework.runtime.SpockRuntime.callBlockExited(this, 1)
  this.getSpecificationContext().getMockController().leaveScope()
}
----

Key rules from Spock source (`SpecRewriter.java`):

* The `blockIndex` matches the 0-based position of the block in the `@FeatureMetadata.blocks` array.
* `where:` blocks do **not** get entry/exit calls (their content becomes separate methods).
* `filter:` blocks do **not** get entry/exit calls (ditto).
* `MockController.leaveScope()` is always emitted at the end of a feature method (line 413: `method.getStatements().add(createMockControllerCall(nodeCache.MockController_LeaveScope))`).

=== Spockk's Current Behaviour

Spockk's `FeatureRewriter` collects block statements and writes them into the feature method body with block label references stripped, but does **not** emit `callBlockEntered/Exited` or `leaveScope`.

'''

'''

== Planned Changes

=== 1. Add IR identifier constants

In `IrIdentifiers.kt`, add:

[source,kotlin]
----
val SPOCK_RUNTIME_FQN = FqName("org.spockframework.runtime.SpockRuntime")
val CALL_BLOCK_ENTERED = CallableId(SPOCK_RUNTIME_FQN, Name.identifier("callBlockEntered"))
val CALL_BLOCK_EXITED = CallableId(SPOCK_RUNTIME_FQN, Name.identifier("callBlockExited"))
val GET_SPECIFICATION_CONTEXT = Name.identifier("getSpecificationContext")
val GET_MOCK_CONTROLLER = Name.identifier("getMockController")
val LEAVE_SCOPE = Name.identifier("leaveScope")
----

=== 2. Add IR builder helpers in `FeatureRewriter`

Add private helpers in `FeatureRewriter` (not in `DeclarationIrBuilder` — these are specific to this rewriter, not shared):

[source,kotlin]
----
// Builds: SpockRuntime.callBlockEntered(this, blockIndex)
private fun irCallBlockEntered(thisParam: IrValueParameter, blockIndex: Int): IrCall

// Builds: SpockRuntime.callBlockExited(this, blockIndex)
private fun irCallBlockExited(thisParam: IrValueParameter, blockIndex: Int): IrCall

// Builds: this.getSpecificationContext().getMockController().leaveScope()
private fun irMockControllerLeaveScope(thisParam: IrValueParameter): IrCall
----

=== 3. Compute block indices in `FeatureRewriter`

The block index passed to `callBlockEntered/Exited` must match the position of the block in `@FeatureMetadata.blocks`. Blocks that are omitted from `@FeatureMetadata.blocks` (i.e., `where:` and `filter:`) must not receive entry/exit calls and must not increment the index counter.

After TODO-1 is applied, only `where:` and `filter:` blocks have `null` blockKind. The index is simply the 0-based count of blocks seen so far with a non-null blockKind.

[source,kotlin]
----
// In FeatureRewriter, when writing block statements:
featureContext.blocks
  .filter { it.label.blockKind != null }  // exclude where:/filter:
  .withIndex()
  .forEach { (blockIndex, block) ->
    functionBody.statements.add(irCallBlockEntered(thisParam, blockIndex))
    functionBody.statements.addAll(block.statements)
    functionBody.statements.add(irCallBlockExited(thisParam, blockIndex))
  }

// Emit MockController.leaveScope() at the end
functionBody.statements.add(irMockControllerLeaveScope(thisParam))
----

=== 4. Handle cleanup block interaction

If the feature has a `cleanup:` block, the feature statements (non-cleanup) are wrapped in try-catch-finally by `CleanupBlockRewriter`. The block entry/exit calls for non-cleanup blocks must be emitted **inside** the try block, and the cleanup block's entry/exit calls must be emitted inside the cleanup's try within the finally. This is handled as part of TODO-3; for now, apply block calls for features without cleanup blocks and leave cleanup-enabled features to TODO-3.

=== 5. Update snapshot tests

All existing compilation snapshot tests for feature methods must be updated to include the `callBlockEntered/Exited` calls and `leaveScope()`.

Example: `transformed/SingleFeatureSpec.kt` currently:

[source,kotlin]
----
fun `$spock_feature_0_0`() {
  assert(true)
}
----

After this change:

[source,kotlin]
----
fun `$spock_feature_0_0`() {
  org.spockframework.runtime.SpockRuntime.callBlockEntered(this, 0)
  assert(true)
  org.spockframework.runtime.SpockRuntime.callBlockExited(this, 0)
  this.getSpecificationContext().getMockController().leaveScope()
}
----
