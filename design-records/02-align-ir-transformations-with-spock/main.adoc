= Align IR Transformations: Matching Spock's Runtime Expectations
:toc:
:toc-title: Contents
:issue: TBD
:date: 2026-03-15

== Context

Spockk reuses Spock's runtime (`spock.lang.Specification`, `org.spockframework.runtime.*`) to execute tests, so Spockk's IR output must match what Spock's AST transformations produce.
Several gaps exist between Spockk's current IR output and what Spock's runtime expects, causing missing block metadata, no block transition events for extensions, and leaked mock state between features.

This design record compares Spockk's current IR transformations against Spock's AST transformations, identifies the differences, and defines a concrete implementation plan to close the gaps.

== Functional Design

=== How Spock Does It

Spock's `SpockTransform` runs during Groovy's `SEMANTIC_ANALYSIS` compile phase in sequential passes:

1. **`SpecParser`** — Parses `ClassNode`s extending `Specification`. Builds a typed model: `Spec -> Method -> Block -> Statement`. Recognises block labels and fixture method names.
2. **`SpecRewriter`** — Applies structural rewrites: renames feature methods, moves field initializers to `$spock_initializeFields()`, wraps cleanup blocks in try-catch-finally, rewrites `when:` blocks for exception conditions, inserts `SpockRuntime.callBlockEntered/Exited()` calls, handles `old()` expression capture.
3. **`SpecAnnotator`** — Adds metadata annotations: `@SpecMetadata`, `@FeatureMetadata`, `@BlockMetadata`, `@FieldMetadata`, `@DataProviderMetadata`, `@DataProcessorMetadata`.
4. **`DeepBlockRewriter` + `ConditionRewriter`** — Rewrites implicit boolean expressions in `then:` and `expect:` blocks into `SpockRuntime.verifyCondition()` calls instrumented with `ValueRecorder`.
5. **`WhereBlockRewriter`** — Transforms `<<` data pipes and data table syntax into data provider/processor/filter methods.

==== Feature Method Transformation

Feature methods are renamed to `$spock_feature_<specDepth>_<ordinal>` and annotated with `@FeatureMetadata` containing block metadata, parameter names, and source location.

==== Block Metadata and Entry/Exit Calls

Each block (except `where:` and `filter:`) maps to a `BlockKind` and gets `SpockRuntime.callBlockEntered(this, blockIndex)` / `callBlockExited(this, blockIndex)` calls around its statements.
`and:` blocks inherit the predecessor's `BlockKind` and merge their description into the preceding block's `texts` array.
Every feature method ends with `this.getSpecificationContext().getMockController().leaveScope()`.

[cols="1,1,2"]
|===
| Label | `BlockKind` | Notes

| `given:` / `setup:` | `SETUP` | `setup:` is an alias for `given:`
| `when:` | `WHEN` |
| `then:` | `THEN` |
| `expect:` | `EXPECT` |
| `cleanup:` | `CLEANUP` | Triggers try-catch-finally wrapping
| `and:` | _(inherits predecessor)_ | Continuation block; merges into preceding block
| `where:` | `WHERE` | Listed in metadata but does NOT get block entry/exit calls
| `filter:` | `FILTER` | Listed in metadata; generates a filter method
|===

==== Cleanup Block Transformation

When a `cleanup:` block is present, `SpecRewriter.visitCleanupBlock()` wraps all preceding block statements in try-catch-finally with a `$spock_failedBlock` variable for block context preservation:

[source,java]
----
Throwable $spock_feature_throwable = null;
try {
  // feature block statements with callBlockEntered/Exited
} catch (Throwable $spock_tmp_throwable) {
  $spock_feature_throwable = $spock_tmp_throwable;
  throw $spock_tmp_throwable;
} finally {
  BlockInfo $spock_failedBlock = null;
  try {
    if ($spock_feature_throwable != null) {
      $spock_failedBlock = this.getSpecificationContext().getCurrentBlock();
    }
    SpockRuntime.callBlockEntered(this, cleanupBlockIndex);
    // cleanup statements
    SpockRuntime.callBlockExited(this, cleanupBlockIndex);
  } catch (Throwable $spock_tmp_throwable) {
    if ($spock_feature_throwable != null) {
      $spock_feature_throwable.addSuppressed($spock_tmp_throwable);
    } else {
      throw $spock_tmp_throwable;
    }
  } finally {
    if ($spock_feature_throwable != null) {
      ((SpecificationContext) this.getSpecificationContext())
        .setCurrentBlock($spock_failedBlock);
    }
  }
}
this.getSpecificationContext().getMockController().leaveScope();
----

=== Gap to Spockk

==== What Spockk does well

* Feature method renaming (`$spock_feature_<specDepth>_<ordinal>`)
* `@FeatureMetadata`, `@FieldMetadata`, `@SpecMetadata` annotations
* Instance/final/`@Shared` field transformations
* Fixture method de-virtualization and field access validation
* Data provider/processor naming and data table transposition
* Mock API transformation (`Mock()`, `Stub()`, `Spy()`)

==== Gaps addressed by this design record

[cols="3,1,1"]
|===
| Gap | Effort | Impact

| `given:` maps to `null` BlockKind instead of `SETUP`; omitted from `@FeatureMetadata.blocks` | Low | Medium
| `and:` does not inherit predecessor's `BlockKind`; omitted from blocks | Low | Medium
| No `SpockRuntime.callBlockEntered/Exited()` calls in feature methods | Medium | *High*
| `MockController.leaveScope()` not called at end of feature methods | Low | *High*
| Cleanup block missing `$spock_failedBlock` / `setCurrentBlock()` pattern | Low | Medium
|===

==== Gaps deferred to future work

* **Implicit conditions in `then:` / `expect:` blocks** — bare boolean expressions require explicit `assert`; full `SpockRuntime.verifyCondition()` + `ValueRecorder` instrumentation deferred
* **Exception conditions (`thrown()` / `notThrown()`)** — `when:` block try-catch wrapping deferred
* **`old()` value capture** — pre-`when:` expression snapshots deferred
* **`filter:` block** — `$spock_feature_N_Mfilter` method generation deferred
* **Full `ValueRecorder` condition instrumentation** — Kotlin power-assert covers the primary use case
* **Mock interaction wiring in `then:` blocks** — full mock interaction rewriting is a separate concern

=== Proposed Approach

All changes are in `spockk-compiler-plugin` and `spockk-specs`.

* Fix `FeatureBlockLabel.GIVEN` to use `blockKind = "SETUP"` and update `FeatureRewriter` to merge `and:` descriptions into the predecessor block
* Add `SpockRuntime.callBlockEntered/Exited` IR calls around each block's statements in `FeatureRewriter`, keyed by block index matching `@FeatureMetadata.blocks` order
* Add `MockController.leaveScope()` call at the end of every feature method
* Update `CleanupBlockRewriter` to produce the full try-catch-finally structure with `$spock_failedBlock`, `getCurrentBlock()`, `setCurrentBlock()`, and block entry/exit calls inside the cleanup
* Update all compilation snapshot tests to match
