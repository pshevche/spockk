== Goal

A `filter:` block following a `where:` block generates a `$spock_feature_N_Mfilter(dataVars...)` method that the Spock runtime calls to determine whether to skip a given iteration.
`filter:` appears in `@FeatureMetadata.blocks` as `BlockKind.FILTER`.

---

== Context and Motivation

=== Spock's Behaviour

Spock added `filter:` blocks in a recent version. The block appears after `where:` and contains boolean expressions (conditions) that, when evaluated, determine whether a given iteration should run.

From `WhereBlockRewriter.createFilterMethod()`:

[source,java]
----
MethodNode filterMethod = new MethodNode(
  InternalIdentifiers.getFilterName(featureName),  // $spock_feature_0_0filter
  Opcodes.ACC_PUBLIC | Opcodes.ACC_SYNTHETIC,
  ClassHelper.VOID_TYPE,
  dataProcessorVars.stream()
    .map(v -> new Parameter(ClassHelper.OBJECT_TYPE, v.getName()))
    .toArray(Parameter[]::new),
  ClassNode.EMPTY_ARRAY,
  blockStat);  // filter: block statements (with condition rewriting applied)
----

Filter method:
* Named `$spock_feature_N_Mfilter`
* Is `public` and `synthetic`
* Returns `void` (conditions are verified via `SpockRuntime.verifyCondition()`)
* Accepts one parameter per data variable (same as the feature method)
* Contains the `filter:` block statements with implicit boolean conditions rewritten

The `filter:` block's `BlockKind.FILTER` appears in `@FeatureMetadata.blocks`.
The runtime calls the filter method before executing each iteration; if a condition fails, the iteration is skipped (not failed).

=== Spockk's Current Behaviour

`filter:` is not recognized as a block label. Users cannot filter iterations at compile time.

=== 4. Update state machine in `ValidatingFeatureBlockCollector.kt`

The state machine must transition:
* `DATA_DEFINITION` (after `where:`) → `FILTER` when `filter:` is encountered.
* `FILTER` is terminal — no transitions out.

[source,kotlin]
----
DATA_DEFINITION -> accepts: filter (-> FILTER)
FILTER -> accepts: nothing (terminal)
----

=== 5. Extract `filterBlock` statements in collector

data class FeatureContext(
  // ... existing fields ...

)
----

=== 6. Generate filter method in `WhereBlockRewriter`

After the data provider and processor methods are generated, if `filterBlock` is non-null:

[source,kotlin]
----
fun rewriteFilterBlock(
  filterBlock: FeatureBlockStatements,
  dataVariables: List<String>,
  featureName: String
) {
  // Apply implicit condition rewriting to filter block statements
  val rewrittenStatements = ImplicitConditionRewriter(context)
    .rewriteBlock(filterBlock)

  // Generate: public synthetic fun $spock_feature_0_0filter(a: Any, b: Any, ...): Unit
  val filterMethod = addMemberFunction(
    name = getDataFilterName(featureName),  // "$spock_feature_0_0filter"
    returnType = unitType
  ).apply {
    // Add data variable parameters
    dataVariables.forEach { varName ->
      addValueParameter(varName, anyNullableType)
    }
    body = irExprBody(irBlock {
      rewrittenStatements.forEach { +it }
    })
    visibility = DescriptorVisibilities.PUBLIC
    isInline = false
  }
  // filterMethod is already added to spec class via addMemberFunction
}
----

Since `FILTER` has a non-null `blockKind`, it will automatically be included in `@FeatureMetadata.blocks` after step 3 is done. Verify that the filter block is added to `FeatureContext.blocks`.

=== Smoke Tests

[source,kotlin]
----
class FilterBlockSmokeSpec : Specification() {
  fun `filter skips iterations where n is odd`(n: Int) {
    io.github.pshevche.spockk.lang.expect
    assert(n % 2 == 0)
    io.github.pshevche.spockk.lang.where
    io.github.pshevche.spockk.lang.variable(n).from(1, 2, 3, 4)
    io.github.pshevche.spockk.lang.filter

  }
}
----

The test should run 2 iterations (n=2, n=4) and skip 2 (n=1, n=3).
