== Goal

Bare boolean expressions in `then:` and `expect:` blocks (without `assert`) should be treated as conditions and cause test failures when they evaluate to `false`, matching Spock's semantics.

---

== Context and Motivation

=== Spock's Behaviour

In Spock, writing:

[source,groovy]
----
then:
result == expected
----

is equivalent to:

[source,groovy]
----
then:
assert result == expected
----

Spock's `ConditionRewriter` transforms the bare boolean into a `SpockRuntime.verifyCondition()` call with `ValueRecorder` instrumentation:

[source,groovy]
----
SpockRuntime.verifyCondition(
  $spock_errorCollector,
  $spock_valueRecorder.reset(),
  "result == expected", line, col, null,
  $spock_valueRecorder.record(
    $spock_valueRecorder.startRecordingValue(0),
    result == expected
  )
)
----

This provides rich failure output showing each sub-expression value.

=== Spockk's Current Behaviour

In Spockk, `then:` and `expect:` block statements are emitted as-is. A bare boolean expression evaluates to a value but the result is discarded — there is no assertion. The test passes even when `result == expected` is `false`.

Users must write explicit `assert result == expected`, which Kotlin's power-assert enhances with rich messages.

=== Design Decision: Option A (Recommended)

**Insert `assert` around bare boolean expressions** in `then:` and `expect:` blocks, leveraging Kotlin power-assert for enhanced failure output.

This is simpler to implement than Option B (full `verifyCondition()` with `ValueRecorder`) and covers the core semantic gap. Kotlin power-assert already provides comparable sub-expression recording. Option B (full Spock-style instrumentation) is deferred to a future design record.

---

== What Qualifies as an Implicit Condition

A statement in a `then:` or `expect:` block is an implicit condition if it is:

* An expression statement whose expression evaluates to a `Boolean` (or `Boolean?`).
* **Not** already wrapped in `assert`.
* **Not** a void expression (method calls returning `Unit`/`void`).
* **Not** an assignment (`=`, `+=`, etc.).
* **Not** a throw statement.
* **Not** a return statement.
* **Not** a variable declaration.

Spock identifies conditions by checking that the expression is not a `MethodCallExpression` to `assert`, not a `DeclarationExpression`, not a `BinaryExpression` with assignment operator, and so on.

Common patterns that ARE implicit conditions:

* `result == expected` (equality)
* `list.isEmpty()` (boolean method call returning Boolean)
* `result` (bare variable reference of Boolean type)
* `a > 0 && b < 10` (compound boolean)

Common patterns that are NOT:

* `println("msg")` (void call)
* `val x = compute()` (declaration)
* `x = 5` (assignment)
* `throw IllegalStateException()` (throw)

== Planned Changes

=== 1. Create `ImplicitConditionRewriter` class

Create a new file:
`spockk-compiler-plugin/src/main/kotlin/io/github/pshevche/spockk/compilation/transformer/condition/ImplicitConditionRewriter.kt`

[source,kotlin]
----
/**
 * Rewrites bare boolean expressions in then:/expect: blocks into assert calls.
 * This matches Spock's implicit condition semantics.
 */
class ImplicitConditionRewriter(override val context: IrGeneratorContext) : SpockkIrRewriter {

  fun rewriteBlock(block: FeatureBlockStatements): List<IrStatement> {
    if (!block.label.isImplicitConditionBlock()) return block.statements
    return block.statements.map { stmt ->
      if (stmt is IrExpressionStatement && isImplicitCondition(stmt.expression)) {
        wrapWithAssert(stmt.expression)
      } else {
        stmt
      }
    }
  }

  private fun isImplicitCondition(expr: IrExpression): Boolean {
    // Must return Boolean or Boolean?
    if (!expr.type.isBoolean() && !expr.type.isNullableBoolean()) return false
    // Must not already be an assert call
    if (expr is IrCall && expr.symbol.owner.name.asString() == "assert") return false
    // Must not be an assignment
    if (expr is IrSetValue || expr is IrSetField) return false
    // Must not be Unit-returning
    if (expr.type.isUnit()) return false
    return true
  }

  private fun wrapWithAssert(expr: IrExpression): IrExpressionStatement {
    // Builds: assert(expr)
    val assertFn = context.irBuiltIns.checkNotNullSymbol  // or find kotlin.assert
    return IrExpressionStatementImpl(
      expr.startOffset, expr.endOffset,
      irBuilder(/* owner */).irCall(assertFn).apply {
        putValueArgument(0, expr)
      }
    )
  }
}
----

== Limitations / Future Work

* This uses Kotlin `assert()` which is controlled by JVM assertion flags (`-ea`). Ensure tests are run with assertions enabled (`-ea` in JVM args or `assert` always-enabled mode). The project likely already enables this via Kotlin's `@AssertionsMode` or by design.
* Option B (full `SpockRuntime.verifyCondition()` with `ValueRecorder`) provides richer output and matches Spock exactly. This is deferred and documented as a future design record.
