= DR-02: Align Spockk IR Transformations with Spock AST Transformations
:toc:
:toc-title: Contents

== Context

Spockk is a Kotlin compiler plugin that replicates Spock's BDD testing syntax in Kotlin.
It transforms Kotlin specs into executable JUnit Platform tests by producing IR (Intermediate Representation) that Spock's runtime (`spockframework/spock`) can interpret via its standard metadata annotations.

Spock itself performs its transformations as Groovy AST transformations at compile time via `SpockTransform`, orchestrating `SpecParser`, `SpecRewriter`, `SpecAnnotator`, `DeepBlockRewriter`, `ConditionRewriter`, and `WhereBlockRewriter`.
Because Spockk reuses Spock's runtime (`spock.lang.Specification`, `org.spockframework.runtime.*`), its IR output must match what Spock's runtime expects.

This document compares Spockk's current IR transformations against Spock's AST transformations, identifies the differences, and defines a concrete implementation plan to close the gaps.

'''

== How Spock Transforms Specs

=== Transformation Pipeline

Spock's `SpockTransform` runs during Groovy's `SEMANTIC_ANALYSIS` compile phase in four sequential passes:

1. **`SpecParser`** — Parses `ClassNode`s extending `Specification`. Builds a typed model: `Spec → Method → Block → Statement`. Recognises block labels and fixture method names.
2. **`SpecRewriter`** — Applies structural rewrites: renames feature methods, moves field initializers to `$spock_initializeFields()`, wraps cleanup blocks in try-catch-finally, rewrites `when:` blocks for exception conditions, inserts `SpockRuntime.callBlockEntered/Exited()` calls, handles `old()` expression capture.
3. **`SpecAnnotator`** — Adds metadata annotations: `@SpecMetadata`, `@FeatureMetadata`, `@BlockMetadata`, `@FieldMetadata`, `@DataProviderMetadata`, `@DataProcessorMetadata`.
4. **`DeepBlockRewriter` + `ConditionRewriter`** — Rewrites implicit boolean expressions in `then:` and `expect:` blocks into `SpockRuntime.verifyCondition()` calls instrumented with `ValueRecorder`.
5. **`WhereBlockRewriter`** — Transforms `<<` data pipes and data table syntax into data provider/processor/filter methods.

=== Feature Method Transformation

==== Renaming

Feature methods are renamed using `$spock_feature_<specDepth>_<ordinal>`:

* `specDepth` — depth of the spec class in the inheritance chain above `Specification` (0 for a direct subclass).
* `ordinal` — 0-based index of the feature within the spec class (source order).

The return type is changed to `void`.

.Example
[source,groovy]
----
// Before
def "aFeature"() { ... }

// After
public void $spock_feature_0_0() { ... }
----

Source: https://github.com/spockframework/spock/blob/master/spock-core/src/main/java/org/spockframework/compiler/SpecRewriter.java[`SpecRewriter.java#createInternalName()`]

==== `@FeatureMetadata` Annotation

Added by `SpecAnnotator.addFeatureMetadata()`:

[source,java]
----
@FeatureMetadata(
  name    = "aFeature",          // original method name
  ordinal = 0,                   // 0-based index within spec
  line    = 5,                   // source line
  blocks  = [ @BlockMetadata(kind=SETUP, texts=["description"]), ... ],
  parameterNames = ["a", "b"]   // parameter names for parametrised features
)
----

==== `@BlockMetadata` Entries

Added for every block whose `BlockParseInfo` is marked as supporting block listeners (all except `where:` and `filter:`). Each block maps to a `BlockKind`:

[cols="1,1,2"]
|===
| Label | `BlockKind` | Notes

| `given:` / `setup:`
| `SETUP`
| `setup:` is an alias for `given:`

| `when:`
| `WHEN`
|

| `then:`
| `THEN`
|

| `expect:`
| `EXPECT`
|

| `cleanup:`
| `CLEANUP`
| Triggers try-catch-finally wrapping

| `and:`
| _(inherits predecessor)_
| Continuation block; adopts the `BlockKind` of the block it follows

| `where:`
| `WHERE`
| Listed in metadata but does NOT get block entry/exit calls

| `filter:`
| `FILTER`
| Listed in metadata; generates a filter method
|===

The `texts` array contains block descriptions (string literals immediately following a label, e.g., `given: "initial state"`); it may be empty.

==== Block Entry/Exit Notification Calls

For every block that supports listeners (all except `where:` and `filter:`), `SpecRewriter.addBlockListeners()` inserts:

[source,java]
----
SpockRuntime.callBlockEntered(this, blockIndex);
// ... block statements ...
SpockRuntime.callBlockExited(this, blockIndex);
----

The `blockIndex` is the 0-based position of the block within `@FeatureMetadata.blocks`, matching array order.
These calls enable Spock extensions to observe block transitions and update `SpecificationContext.getCurrentBlock()`.

At the end of every feature method, `MockController.leaveScope()` is called:

[source,java]
----
this.getSpecificationContext().getMockController().leaveScope()
----

==== Implicit Condition Rewriting

In `then:` and `expect:` blocks, `ConditionRewriter` transforms every bare boolean expression (without explicit `assert`) into a verified condition:

[source,groovy]
----
// Developer writes:
then:
result == expected

// Spock transforms into:
SpockRuntime.verifyCondition(
  $spock_errorCollector,
  $spock_valueRecorder.reset(),
  "result == expected", line, col, null,
  $spock_valueRecorder.record(
    $spock_valueRecorder.startRecordingValue(0),
    result == expected
  )
)
----

This requires `ValueRecorder` and `ErrorCollector` instances to be declared at the top of the feature method.

=== Cleanup Block Transformation

When a `cleanup:` block is present, `SpecRewriter.visitCleanupBlock()` wraps all preceding block statements in try-catch-finally:

[source,java]
----
Throwable $spock_feature_throwable = null;
try {
  // setup/when/then/expect block statements
  // (with SpockRuntime.callBlockEntered/Exited around each)
} catch (Throwable $spock_tmp_throwable) {
  $spock_feature_throwable = $spock_tmp_throwable;
  throw $spock_tmp_throwable;
} finally {
  BlockInfo $spock_failedBlock = null;
  try {
    if ($spock_feature_throwable != null) {
      $spock_failedBlock = this.getSpecificationContext().getCurrentBlock();
    }
    SpockRuntime.callBlockEntered(this, cleanupBlockIndex);
    // cleanup statements
    SpockRuntime.callBlockExited(this, cleanupBlockIndex);
  } catch (Throwable $spock_tmp_throwable) {
    if ($spock_feature_throwable != null) {
      $spock_feature_throwable.addSuppressed($spock_tmp_throwable);
    } else {
      throw $spock_tmp_throwable;
    }
  } finally {
    if ($spock_feature_throwable != null) {
      ((SpecificationContext) this.getSpecificationContext())
        .setCurrentBlock($spock_failedBlock);
    }
  }
}
----

Key points:

* `$spock_feature_throwable` starts `null` (not `EmptyExpression`): `null` means no exception was thrown.
* The `$spock_failedBlock` variable preserves the `BlockInfo` of the currently executing block when an exception occurs, so extensions can report the correct failed block even after cleanup transitions to the cleanup block.
* `addSuppressed()` is used to chain cleanup exceptions onto feature exceptions.
* `setCurrentBlock($spock_failedBlock)` is restored in a `finally` inside the cleanup try-catch.

=== Exception Condition Handling (`thrown()` / `notThrown()`)

When `thrown()` or `notThrown()` appears in a `then:` block, `SpecRewriter.rewriteWhenBlockForExceptionCondition()` wraps the preceding `when:` block:

[source,java]
----
// Inserted at start of when:
setThrownException(null);

// when statements become:
try {
  // when statements (variable declarations hoisted before try)
} catch (Throwable $spock_ex) {
  setThrownException($spock_ex);
}
----

The `thrown(Type)` / `notThrown()` call in `then:` reads from `thrownException` via `Specification.getThrownException()` at runtime.

=== `old()` Value Capture

`old(expr)` in a `then:` block captures `expr` **before** the `when:` block executes.
`ConditionRewriter` / `DeepBlockRewriter` detects `old()` calls and emits:

[source,java]
----
// Inserted before the when: block:
def $spock_old_value0 = <expr>

// old(expr) in then: block replaced by:
$spock_old_value0
----

=== Spec Field Transformation

`SpecRewriter.visitField()` applies different strategies based on field type:

==== Instance Non-Final Fields

* **No renaming** — field name is unchanged.
* Field initializer is moved to `$spock_initializeFields()` via `FieldInitializationExpression`.
* Field itself gets `@FieldMetadata(name, ordinal, line, initializer=true/false)`.

==== Instance Final Fields

* **Renamed** to `$spock_finalField_<name>`.
* `final` modifier removed.
* Field initializer moved to `$spock_initializeFields()`.
* A **getter method** is generated with the field's original name (e.g., `getAnswer()`).
* Field is annotated with `@FieldMetadata`.

==== `@Shared` Fields

* **Renamed** to `$spock_sharedField_<name>`.
* Visibility changed to `protected` (not private — required for cross-instance access, see `SpecRewriter` comment lines 230-270).
* `volatile` modifier added (`ACC_VOLATILE`).
* `final` modifier removed (if present).
* Field initializer moved to `$spock_initializeSharedFields()`.
* A **getter** is generated that reads from `getSpecificationContext().getSharedInstance()`.
* For non-final `@Shared` fields, a **setter** is also generated that writes to the shared instance.
* Field is annotated with `@FieldMetadata`.

.`$spock_initializeFields()` method
[source,java]
----
// Created lazily by SpecRewriter.getInitializerMethod()
private Object $spock_initializeFields() {
  // one FieldInitializationExpression per field with an initializer
  foo = 'bar'
}
----

The method is `private` so that multiple initializer methods along the hierarchy can be called independently via reflection.

=== Fixture Method Transformation

`SpecRewriter.visitMethod()` handles `FixtureMethod` instances:

1. **De-virtualization**: Changes visibility to `private` (`ACC_PRIVATE`). This ensures that if both `Base` and `Derived` declare `setup()`, both can be invoked independently via reflection without virtual dispatch hiding the parent.
2. **Field access validation** (for `setupSpec` / `cleanupSpec` only): `InstanceFieldAccessChecker` verifies that the method body does not access instance fields — only `@Shared` and static members are permitted.

Fixture methods do **not** receive any metadata annotation (`@FeatureMetadata` is only for feature methods).
Fixture methods keep their original names after transformation.

=== Data Parametrization (Where Block)

`WhereBlockRewriter` transforms `where:` block content:

* **Data pipes** (`x << [1,2,3]`) and **data tables** (`x | y \n 1 | 2`) are both normalised into data providers.
* **Data tables** are transposed column-by-column; each column becomes a separate data provider.
* **Data provider methods** are named `$spock_feature_N_Mprov<index>` (public, synthetic).
* **Data processor method** is named `$spock_feature_N_Mproc` (public, synthetic).
* **Filter method** (if a `filter:` block exists) is named `$spock_feature_N_Mfilter` (public, synthetic).
* Provider methods accept `List` parameters for columns that reference previous data table variables.
* Processor method accepts one parameter per provider and returns `Object[]` of the data variables.

For a multi-parameterization `[x, y] << list`:

[source,groovy]
----
// Generated processor:
a = ($spock_p0 instanceof Map ? $spock_p0.getAt('a') : $spock_p0.getAt(0)) as Object
b = ($spock_p0 instanceof Map ? $spock_p0.getAt('b') : $spock_p0.getAt(1)) as Object
----

'''

== How Spockk Currently Transforms Specs

=== What Spockk Does Well

Spockk correctly implements the following transformations that match Spock:

* **Feature method renaming**: `$spock_feature_<specDepth>_<ordinal>` format is identical.
* **`@FeatureMetadata` annotation**: `name`, `ordinal`, `line`, `parameterNames` fields are correct.
* **`@FieldMetadata` annotation**: All four fields (`name`, `ordinal`, `line`, `initializer`) are correct.
* **`@SpecMetadata` annotation**: `filename` and `line` are correct.
* **Instance final field transformation**: Renamed to `$spock_finalField_<name>`, getter generated, initializer moved to `$spock_initializeFields()`.
* **Instance non-final field transformation**: Initializer moved to `$spock_initializeFields()`, made nullable.
* **`@Shared` field transformation**: Renamed to `$spock_sharedField_<name>`, protected volatile, getter routing through `sharedInstance`, initializer moved to `$spock_initializeSharedFields()`.
* **Fixture method de-virtualization**: Made `private`.
* **`setupSpec` / `cleanupSpec` field access validation**: Instance fields rejected.
* **Data provider / processor naming**: Identical to Spock.
* **Data table transposition into simple pipes**: Matches Spock logic.
* **Mock API transformation**: `Mock()`, `Stub()`, `Spy()` augmented with name and type metadata.
* **Cleanup block try-catch-finally structure**: Core exception-chaining logic matches Spock.

=== Gaps Identified

The following differences were found between Spockk's current IR output and what Spock produces.

==== Gap 1: `given:` maps to `null` BlockKind instead of `BlockKind.SETUP`

*Spock*: `given:` → `BlockKind.SETUP` (appears in `@FeatureMetadata.blocks`) +
*Spockk*: `GIVEN` has `blockKind = null` in `FeatureBlockLabel.kt` → omitted from `@FeatureMetadata.blocks`

Blocks with `null` blockKind are filtered out in `FeatureRewriter.kt`.
This means `given:` blocks are invisible to Spock extensions and the runtime's block metadata.

==== Gap 2: `and:` does not inherit its predecessor's `BlockKind`

*Spock*: `and:` inherits the `BlockKind` of the preceding block (e.g., `and:` after `then:` becomes `THEN`). +
*Spockk*: `AND` has `blockKind = null` → omitted from `@FeatureMetadata.blocks`

Every block in a feature except `where:` / `filter:` should appear in `@FeatureMetadata.blocks` with the correct kind and descriptions.
This is confirmed by Spock's snapshot: `all_observable_blocks_with_labels_and_blocks.groovy` shows `and:` after `then:` produces `BlockKind.THEN`.

==== Gap 3: No block entry/exit notification calls

*Spock*: Every block (except `where:` and `filter:`) gets `SpockRuntime.callBlockEntered(this, i)` / `callBlockExited(this, i)` around its statements. +
*Spockk*: No such calls are emitted.

This is the highest-impact gap. Spock extensions that observe block transitions receive no events.
`SpecificationContext.getCurrentBlock()` is never updated, causing `NullPointerException`s in extensions that read it.
The cleanup block transformation in Spockk also omits the `$spock_failedBlock` pattern needed for proper block context restoration.

==== Gap 4: `MockController.leaveScope()` is not called

*Spock*: Every feature method ends with `this.getSpecificationContext().getMockController().leaveScope()`. +
*Spockk*: This call is absent.

Without it, mock scopes created during `when:` blocks are never closed, leaking mock state between features.

==== Gap 5: Implicit conditions in `then:` / `expect:` are not rewritten

*Spock*: Bare boolean expressions in `then:` and `expect:` are wrapped in `SpockRuntime.verifyCondition()` with `ValueRecorder` instrumentation. +
*Spockk*: Bare boolean expressions produce no assertion error when false; users must write explicit `assert`.

This is a core Spock idiom difference.
Spockk does use Kotlin power-assert for explicit `assert` statements, which provides rich output, but bare booleans are silently ignored.

==== Gap 6: No exception condition support (`thrown()` / `notThrown()`)

*Spock*: `thrown(Type)` in `then:` causes the `when:` block to be wrapped in try-catch, capturing thrown exceptions. +
*Spockk*: `thrown()` / `notThrown()` are not detected at compile time; the `when:` block is not rewritten.

==== Gap 7: No `old()` value capture

*Spock*: `old(expr)` in `then:` is replaced with a variable capturing `expr` before the `when:` block runs. +
*Spockk*: `old()` is not supported.

==== Gap 8: Cleanup block missing `$spock_failedBlock` / `setCurrentBlock()` pattern

*Spock*: The cleanup block's finally structure includes a `$spock_failedBlock` variable and a nested `finally { setCurrentBlock($spock_failedBlock) }` to restore block context after cleanup. +
*Spockk*: The current `CleanupBlockRewriter` generates a simpler try-catch-finally that omits this context restoration. This prevents Spock extensions from correctly identifying which block failed.

==== Gap 9: `filter:` block is not supported

*Spock*: A `filter:` block after `where:` generates a `$spock_feature_N_Mfilter(dataVars...)` method and appears in `@FeatureMetadata.blocks` as `BlockKind.FILTER`. +
*Spockk*: No `filter:` support; the block label is not recognised.

==== Gap 10: Data processor uses separate providers per data table column; Spock uses per-provider method

Both Spock and Spockk generate one provider method per data variable (column).
However, Spock's `@DataProviderMetadata` does not set `previousDataTableVariables` for data pipes — only for data tables where earlier column values are referenced.
Spockk currently always sets `previousDataTableVariables` for all but the first column of a data table, even when no cross-column references exist.
This is a minor annotation difference that does not affect runtime correctness today but diverges from Spock's intent.

== Out of Scope

* **Implicit conditions in `then:` / `expect:` blocks**: Bare boolean expressions currently require an explicit `assert`. Making them implicit conditions is deferred to a future release. When implemented, the recommendation is to wrap bare booleans with `assert` first (delegating to Kotlin power-assert), with full `SpockRuntime.verifyCondition()` + `ValueRecorder` instrumentation as a later follow-up.
* **Exception conditions (`thrown()` / `notThrown()`)**: Wrapping `when:` blocks in try-catch when `thrown()` / `notThrown()` is detected in `then:` is deferred to a future release.
* **`old()` value capture**: Capturing pre-`when:` expression snapshots via `old(expr)` is deferred to a future release. `old()` is not required for mock interaction testing.
* **`filter:` block**: Generating a `$spock_feature_N_Mfilter` method from a `filter:` block after `where:` is deferred to future work.
* **Full `ValueRecorder` condition instrumentation**: Rich sub-expression recording matching Spock's exact output requires significant IR work. Kotlin power-assert covers the primary use case and is already integrated. Full instrumentation is deferred to a separate design record.
* **Mock interaction wiring in `then:` blocks**: Moving mock interactions before the `when:` block and wrapping with `MockController.enterScope()` / `leaveScope()` is partially covered by the `MockController.leaveScope()` fix in TODO-2 but the full mock interaction rewriting is a separate concern.
* **`@Unroll` iteration naming**: `#paramName` interpolation in feature names is handled by Spock's runtime iteration runner. No IR changes are needed unless Spockk adds its own naming templates.
