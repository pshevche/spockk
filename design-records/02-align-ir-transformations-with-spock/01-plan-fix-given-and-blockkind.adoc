= Plan: Fix `given:` and `and:` BlockKind Mapping
:toc:
:toc-title: Contents

== Overview

Fix two block label mapping issues so that `given:` blocks appear in `@FeatureMetadata.blocks` as `BlockKind.SETUP`, and `and:` blocks merge their descriptions into the preceding block's `texts` array (matching Spock's `SpecParser` behaviour).

This is the first increment because correct block metadata is a prerequisite for block entry/exit calls (plan 02) and cleanup block context restoration (plan 03).

== Changes

=== `spockk-compiler-plugin/.../common/FeatureBlockLabel.kt`

Change `GIVEN` to use `"SETUP"` as its `blockKind`:

[source,kotlin]
----
// Before:
GIVEN("given", GIVEN_BLOCK_FQN, null),

// After:
GIVEN("given", GIVEN_BLOCK_FQN, "SETUP"),
----

=== `spockk-compiler-plugin/.../transformer/FeatureRewriter.kt`

Update the block merging logic so that when `and:` appears, its description is appended to the preceding block's description list rather than creating a new block metadata entry.
The block filter `blocks.filter { it.element.label.blockKind != null }` already excludes `AND` (which keeps `blockKind = null`), so no change is needed there once the merging handles descriptions.

Add a `doMergeBlocks()` method that iterates through blocks, merging `and:` blocks into the previous block's descriptions and statements lists:

[source,kotlin]
----
for (block in blocks) {
  if (label == FeatureBlockLabel.AND && result.isNotEmpty()) {
    val last = result.last()
    result[result.lastIndex] = last.copy(
      descriptions = last.descriptions + block.element.description,
      statements = last.statements + block.statements
    )
  } else if (label.blockKind != null) {
    result.add(MergedBlock(blockKind = label.blockKind!!, descriptions = listOf(block.element.description), ...))
  }
}
----
