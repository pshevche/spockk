= Plan: Add setup and cleanup block labels
:toc:
:toc-title: Contents

== Overview

Register `setup` and `cleanup` as first-class block labels in `spockk-core` and `spockk-compiler-plugin`. `setup` is an alias for `given` (same semantics, different name). `cleanup` is a new terminal block that can follow `then` or `expect`. Update the block validation state machine to accept both.

This increment delivers the compiler-side foundation for both block labels and includes error scenario tests and a smoke test for `setup`. The `cleanup` block transformation (try-catch-finally wrapping) is a separate increment.

== Changes

=== `spockk-core/.../lang/Blocks.kt`

Add `setup` and `cleanup` label objects and functions alongside the existing ones:

[source,kotlin]
----
object setup {
  init {
    throwIllegalLabelUsageException("setup")
  }
}

fun setup(description: String) {
  throwIllegalLabelUsageException("setup")
}

object cleanup {
  init {
    throwIllegalLabelUsageException("cleanup")
  }
}

fun cleanup(description: String) {
  throwIllegalLabelUsageException("cleanup")
}
----

=== `spockk-compiler-plugin/.../ir/IrIdentifiers.kt`

Add FQN constants for the new block labels:

[source,kotlin]
----
val SETUP_BLOCK_FQN = LANG_PKG_FQN.child("setup")
val CLEANUP_BLOCK_FQN = LANG_PKG_FQN.child("cleanup")
----

=== `spockk-compiler-plugin/.../common/FeatureBlockLabel.kt`

Add `SETUP` and `CLEANUP` entries. `SETUP` maps to the same `BlockKind` as `GIVEN` (null — Spockk uses null for setup/given which need no special runtime annotation):

[source,kotlin]
----
SETUP("setup", SETUP_BLOCK_FQN, null),
CLEANUP("cleanup", CLEANUP_BLOCK_FQN, "CLEANUP"),
----

=== `spockk-compiler-plugin/.../common/FeatureBlockLabelIrElement.kt`

Add `Setup` and `Cleanup` data classes:

[source,kotlin]
----
data class Setup(
  override val description: String,
  override val file: IrFile,
  override val ir: IrElement
) : FeatureBlockLabelIrElement(FeatureBlockLabel.SETUP, description, file, ir)

data class Cleanup(
  override val description: String,
  override val file: IrFile,
  override val ir: IrElement
) : FeatureBlockLabelIrElement(FeatureBlockLabel.CLEANUP, description, file, ir)
----

Add both to the `fromElement()` mapping.

=== `spockk-compiler-plugin/.../collector/ValidatingFeatureBlockCollector.kt`

Update the state machine:

* In `INIT`, accept `FeatureBlockLabelIrElement.Setup` with the same transition as `Given` (→ `PRECONDITION`)
* Add a new `CLEANUP` state that only accepts `And` continuations:

[source,kotlin]
----
CLEANUP {
  override val validBlocks: List<FeatureBlockLabel>
    get() = listOf(FeatureBlockLabel.AND)

  override fun nextOrFailIfInvalid(block: FeatureBlockLabelIrElement): State =
    when (block) {
      is FeatureBlockLabelIrElement.And -> this
      else -> failOnInvalidBlock(block)
    }
}
----

* In `EXPECTATION_EXPECT` and `EXPECTATION_THEN`, add `FeatureBlockLabel.CLEANUP` to `validBlocks` and the `Cleanup -> CLEANUP` transition
* Add `CLEANUP` to the `isTerminal()` check

== Test Plan

=== Compilation Tests (Snapshot-Based)

No snapshot tests for this increment — the `setup` block has identical IR output to `given`, so no new snapshot is needed. The `cleanup` block transformation (try-catch-finally) is covered in increment 4.

=== Error Scenario Tests (Inline Specs)

These belong in `FeatureBlockStructureValidationTest`:

* `cleanup` block appearing before `then`/`expect` → error
* `cleanup` block followed by a non-`and` block (e.g., `when`) → error
* Consecutive `setup` blocks (two `setup:` in the same feature) → error

=== Smoke Tests (End-to-End)

* `SetupBlockSmokeTest` — verifies `setup:` block executes as expected, confirms it is equivalent to `given:`

=== Runtime Tests (Engine Tests)

None for this increment.
