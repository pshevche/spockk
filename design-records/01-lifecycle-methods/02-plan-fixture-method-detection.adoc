= Plan: Add fixture method detection
:toc:
:toc-title: Contents

== Overview

Extend the collection phase to recognize and track fixture methods (`setup`, `cleanup`, `setupSpec`, `cleanupSpec`). Currently these are silently ignored; after this increment they are explicitly identified and stored in the transformation context. Also adds compile-time validation (no duplicate methods, no block labels inside, no `super.` calls).

This increment has no visible user-facing change on its own — fixture methods still compile but aren't transformed until increment 3.

== Changes

=== `spockk-compiler-plugin/.../common/SpockkTransformationContext.kt`

Add a `FixtureMethodKind` enum and extend `SpecContext` to hold fixture methods:

[source,kotlin]
----
enum class FixtureMethodKind {
  SETUP, CLEANUP, SETUP_SPEC, CLEANUP_SPEC
}

data class SpecContext(
  val fileName: String,
  val line: Int,
  val features: Map<IrFunction, FeatureContext>,
  val fields: Map<IrProperty, FieldContext>,
  val fixtureMethods: Map<IrFunction, FixtureMethodKind>  // NEW
)
----

=== `spockk-compiler-plugin/.../common/MutableSpockkTransformationContext.kt`

Add fixture method tracking to `MutableSpecContext`:

[source,kotlin]
----
val fixtureMethods: MutableMap<IrFunction, FixtureMethodKind> = mutableMapOf()

fun addFixtureMethod(function: IrFunction, kind: FixtureMethodKind) {
  fixtureMethods[function] = kind
}
----

Wire `finalized()` to include `fixtureMethods` in the immutable `SpecContext`.

=== `spockk-compiler-plugin/.../collector/SpockkTransformationContextCollector.kt`

Modify `visitFunctionNew()` to detect fixture methods before falling through to block collection. A function is a fixture method if:

* It belongs to a spec class (tracked via `maybeCurrentIrClass`)
* Its name is one of `setup`, `cleanup`, `setupSpec`, `cleanupSpec`
* It is NOT a fake override

When detected, call `context.addFixtureMethod(function, kind)` and return early (do not collect blocks from it).

Add validation during detection:

* Duplicate fixture method (two `setup()` in the same spec class) → compilation error
* Fixture method contains block labels (`given:`, `when:`, etc.) → compilation error
* Fixture method contains a `super.setup()` / `super.cleanup()` call → compilation error (these calls would fail at runtime after de-virtualization makes the method private)
